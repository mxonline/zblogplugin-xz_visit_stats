# xz_visit_stats v3.0.0 → v4.0.0 升级说明

## 升级前

1. 备份当前插件目录与数据库，并记录原始访问日志数量。
2. 确认目标站点为 PHP 7.1+，并在 Windows 验收基线中核对 Z-BlogPHP 与 MySQL 版本。
3. 保留现有插件目录名 `xz_visit_stats`；不要先删除 v3 数据表或历史备份。

## 升级步骤

1. 将 `xz_visit_stats-v4.0.0.zip` 解压至 `zb_users/plugin/`，确认结构为 `zb_users/plugin/xz_visit_stats/`。
2. 在 Z-BlogPHP 插件管理中启用“访问统计”。安装钩子会执行结构检查和增量迁移。
3. 打开插件后台，检查总览、记录、来源、内容、访客、蜘蛛、事件和设置页面。
4. 在 MySQL 中确认 v3 原始表及历史日志仍存在，且插件配置的 `db_version` 达到 `4.0.0`。

迁移先核验表、列和索引，再补齐缺少项；重复执行不会删除旧表、重建历史表或重复创建已有结构。若发现同名结构定义不一致，迁移应停止并保留当前数据，先检查备份与审计结果。

## 数据与统计口径

- v3 原始访问日志、已有小时/日汇总和历史记录继续保留。
- v4 以新增会话、页面序列和事件表保存对应数据；卸载/停用插件不会清空历史表。
- 历史 v3 行没有 v4 页面生命周期数据，因此不推算历史停留时长或跳出率。页面可以显示部分覆盖或不可用状态。
- `vs_DurationMs` 仍是服务器处理耗时，不能作为访客停留时长。
- Beacon 默认关闭。启用后再开始接收页面生命周期与事件数据，不回填升级前的用户浏览时长。

## 回滚边界

若升级后需要暂时回到旧版本，先在插件管理中停用插件并保留全部 v3/v4 数据表。不要通过 `DROP TABLE`、重建旧表或清空插件数据回滚。只有在隔离恢复环境验证过备份后，才可另行制定数据库恢复步骤；不要把本机测试备份覆盖到生产数据库。
