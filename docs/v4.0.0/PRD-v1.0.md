# xz_visit_stats v4.0 — 51.LA 对标 PRD v1.0

## 1. 产品定位

在 xz_visit_stats v3.0 的服务端访问采集基础上，升级为面向站长的“访问分析中心”。

v4.0 参考已完成调研的 51.LA V6 后台信息架构，但不做商业功能照搬。界面继续沿用现有插件已经形成的视觉与交互语言：顶部 KPI 卡片、时间范围切换、趋势图、筛选栏、明细表格、会话/访客下钻，以及概览、访问、蜘蛛、设置等后台结构。

目标不是单纯增加更多统计数字，而是让站长能回答四类问题：

- 网站现在有多少真实访问；
- 流量从哪里来、进入了哪些页面；
- 一个访客在站内看了什么、停留多久、是否继续浏览；
- 搜索引擎和蜘蛛抓取了哪些页面、是否存在异常。

## 2. v4.0 功能范围

### 2.1 访问总览

核心 KPI：

- PV
- UV
- IP
- 会话数
- 跳出率
- 平均停留时长

总览同时展示：

- 新访客 / 老访客
- 来源类型
- 热门页面
- 入口页面
- 地域
- 设备类型
- 浏览器 / 操作系统概览

时间范围至少支持今天、昨天、近 7 天、近 30 天及自定义范围。

### 2.2 实时访客

支持 5 / 15 / 30 分钟窗口，展示：

- 当前活跃访客数
- 当前访问来源
- 当前入口页
- 最近浏览页面
- 浏览器 / 设备
- 地域分布

实时列表应可进入对应会话详情。

### 2.3 趋势分析

支持按小时、日、周、月查看 PV / UV / IP / 会话趋势，并提供同环比。

筛选维度包括：

- 设备
- 新老访客
- 来源
- 省份 / 地域

常用趋势优先从小时 / 日汇总表读取，避免大数据量下每次扫描原始访问日志。

### 2.4 访问明细

明细字段至少包括：

- 访问时间
- 访客标识
- IP
- 国家 / 省份
- 浏览器
- 操作系统
- 设备
- 来源类型
- 来源域名
- 入口页面
- 当前页面
- 搜索关键词
- 会话页数
- 停留时长
- HTTP 状态码

支持：

- 时间范围筛选
- 来源筛选
- 设备筛选
- 地域筛选
- 蜘蛛 / 真人筛选
- 列显示配置
- 受控导出
- 会话下钻

### 2.5 来源分析

来源分类：

- 直接访问
- 搜索引擎
- 外部链接
- AI 来源
- UTM 来源

搜索分析至少包含搜索引擎、来源域名和可解析关键词。

v3 已有 UTM 与 AI 来源字段继续保留并增强，但不单独建立“渠道追踪”产品模块。

### 2.6 内容分析

支持：

- 浏览页面排行
- 入口页面排行
- 目录分析
- 域名 / Host 分析

目录分析允许定义目录规则和排除规则，用于区分文章、栏目、专题或自定义路径。

### 2.7 访客分析

支持：

- 新访客 / 老访客
- 访问深度
- 会话页数
- 设备
- 操作系统
- 浏览器
- 分辨率
- 语言
- 国家 / 地区 / 省份
- 运营商
- IP

访客标识必须使用不可逆散列，不保存可逆的跨站身份数据。

### 2.8 蜘蛛分析

支持：

- 搜索引擎 / 爬虫类型
- 蜘蛛访问次数
- 蜘蛛 IP
- 抓取 URL
- 最后访问时间
- 抓取明细
- HTTP 状态码

至少保持对 Googlebot、Baiduspider、bingbot 以及现有其他机器人分类的兼容。

### 2.9 事件分析

新增代码埋点和自定义事件能力。

事件核心指标：

- 事件总量
- 触发次数
- 独立触发用户
- 人均触发次数

v4.0 只做代码埋点，不复制 51.LA 的可视化埋点编辑器。

### 2.10 设置与数据管理

包括：

- 采集开关
- 客户端 Beacon 开关
- IP 过滤
- 蜘蛛采集策略
- 数据保留期
- 数据下载 / 导出任务
- 隐私说明
- 数据维护状态

## 3. 明确排除

v4.0 不实现：

- 渠道追踪独立模块
- 热力图
- 屏幕录制
- 51.LA 商业配额体系
- 51.LA 可视化埋点编辑器
- 51.LA 智能 IP 过滤功能的原样复刻

## 4. 统计口径

### 4.1 PV

一条符合采集规则的页面访问记录计为 1 PV。静态资源、后台页面和插件后台请求继续按现有规则排除。

### 4.2 UV

在所选统计周期内按 VisitorHash 去重。

### 4.3 IP

在所选统计周期内按有效统计 IP 去重，受 ip_mode 和过滤规则影响。

### 4.4 会话

v4 新增会话语义。相同访客在会话超时窗口内连续访问归为同一 Session。

具体超时值在 T3 技术设计中固化，并要求迁移后可兼容已有访问日志。

### 4.5 停留时长

v3 的 `vs_DurationMs` 是服务器请求处理耗时，只能用于性能指标，禁止作为用户停留时长。

v4 的页面停留和会话停留需要通过页面序列、客户端生命周期 Beacon 与会话规则计算。

### 4.6 跳出率

以只包含一个有效页面浏览的会话为跳出会话。不能使用单条 v3 日志直接推断。

## 5. 数据与迁移原则

- 保留 v3 原始访问日志。
- 保留既有小时 / 日汇总能力。
- 新增会话、页面序列、事件、目录规则、导出任务等结构时只采用增量迁移。
- 不删除历史字段，不通过不可逆 DDL 覆盖 v3 数据。
- 所有迁移必须可重复执行。
- 真实表结构未在 Windows 本地 Z-Blog 环境审计前，不锁定最终迁移 SQL。

## 6. 隐私与权限

- VisitorHash 使用不可逆散列。
- IP 采集支持完整 / 脱敏模式。
- 导出功能仅对有权限的后台管理员开放。
- 不在审计或调试报告中导出访客级数据、数据库密码、Token 或 Cookie。
- 数据保留期必须可配置。

## 7. 后台交互原则

v4 后台以“先看总览，再下钻原因”为主线。

标准页面结构：

1. 页面标题与时间范围。
2. KPI 卡片。
3. 趋势图或维度图。
4. 筛选栏。
5. 明细表 / 排行表。
6. 点击维度进入会话、访客、页面或来源下钻。

避免把所有维度堆在一个超长页面中。

## 8. 实施阶段

### T2 — 真实结构审计与迁移设计

只读导出本地 Z-Blog 真实表结构、索引、行数、运行时版本和安全配置，形成 v4 增量迁移设计依据。

### T3 — 采集与统计基础

实现会话识别、页面序列、停留 / 跳出、事件、IP 过滤及基础汇总。

### T4 — 报表与后台体验

实现总览、实时、趋势、明细、来源、内容、访客、蜘蛛、事件和设置页面。

### T5 — Windows 本地验证与发布准备

执行真实安装 / 升级、采集、统计口径、性能、后台 UI、CI 和 Release Gate。

## 9. 发布边界

v4.0 属于大版本升级。没有完成真实 Windows Z-Blog 运行时验证、数据库迁移验证和回归检查前，不得标记为完成、可发布或已发布。
