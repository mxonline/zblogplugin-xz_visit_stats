# xz_visit_stats v2.0 正式 PRD v1.1

状态：**FROZEN｜需求已冻结**。本版已合并 PRD v1.0 产品评审结论，并通过最终冻结检查，作为 v2.0 正式产品需求基线。后续不再继续生成新的 PRD 版本；只有新增/删除 P0、改变统计语义或用户可见口径时才允许变更本 PRD。

产品定位：**站长访问分析中心**。

## 1. 产品目标

xz_visit_stats v2.0 面向 Z-Blog PHP 站长，将现有访问统计能力升级为用于日常运营、SEO 来源观察、蜘蛛抓取分析、错误排查和数据维护的一体化访问分析后台。

v2.0 必须帮助站长快速回答五个问题：谁来了、从哪里来、看了什么、蜘蛛抓了什么、哪里异常。

产品目标不是堆叠指标，而是让站长从“看到数据”继续走到“定位原因”。

## 2. 目标用户

- 使用 Z-Blog PHP 的个人站长和内容站维护者；
- 希望在本地掌握访问、来源、蜘蛛和错误数据的站长；
- 需要快速定位 404、5xx、异常来源、服务端慢请求和蜘蛛抓取问题的维护者；
- 不希望完全依赖外部统计平台的站点运营者。

## 3. 设计原则

- 产品需求优先；v1.3 数据用于历史兼容和可实现性校验，不作为产品需求来源。
- 默认站长主视图以**真人访问**为核心，蜘蛛访问独立展示，避免混淆流量判断。
- 历史可计算指标保持兼容；历史无法可靠回算的能力必须标记“仅升级后统计”或移出 v2.0。
- 不把 v2.0 做成 WAF、全功能 SEO 排名平台或复杂用户行为分析系统。
- 不提供无法由现有数据证明的伪精确指标。
- 所有图表和聚合分析尽量支持下钻到具体访问记录或模块详情。
- 常用查询必须具备可长期运行的数据架构，不能依赖无界全表扫描。
- 数据库、升级、Hook、采集、后台页面和汇总逻辑必须经过真实 Z-Blog 环境验证。

## 4. 后台信息架构

插件保持一个主入口“访问分析”，内部提供 7 个固定模块：总览、访问记录、页面分析、来源分析、蜘蛛分析、错误分析、设置与维护。默认进入“总览”，不再新增一级菜单。

## 5. 优先级定义

- **P0**：v2.0 首发必须完成，缺失即不能发布 2.0。
- **P1**：v2.0 应完成或 2.0.x 优先补齐，不作为 2.0.0 首发硬门槛。
- **P2**：2.1 / 2.2 候选，不进入 2.0.0 首发范围。

## 6. P0｜数据总览

默认主 KPI 仅统计真人访问：访客 PV、访客 UV、访客独立 IP、4xx、5xx、平均服务端处理耗时；蜘蛛访问量独立展示，总请求量可作为辅助指标。支持今天、昨天、最近 7 天、最近 30 天和自定义日期范围，统一使用 Z-Blog 站点时区并按站点本地 00:00:00 切分日界线。

总览包括真人 PV/UV/IP 趋势、真人/蜘蛛趋势、来源类型占比、热门页面、蜘蛛排行、错误摘要、周期对比、采集状态、最近访问数据时间、最近汇总时间和数据库/汇总异常状态。

主要聚合项必须支持下钻，并带入时间范围和筛选条件。无数据时显示 0 或空状态；采集关闭、数据延迟或汇总异常时给出明确提示；7/30 天常用查询不能依赖无界全表扫描。

## 7. P0｜访问记录

展示访问时间、IP、真人/蜘蛛、蜘蛛名称、URL/Path、来源类型、Referer、浏览器、操作系统、设备类型、HTTP 状态码和服务端处理耗时。支持时间、IP、URL/Path、真人/蜘蛛、蜘蛛类型、来源类型、状态码、浏览器和设备类型筛选，并提供最近 5/15/30 分钟、仅蜘蛛、仅错误请求、服务端慢请求快速视图。

记录详情可以展示完整 URL、Referer、UA、解析结果和该 IP 的近期访问摘要。IP 归属地不作为 P0 硬门槛。分页必须稳定，多条件组合正确，输入严格校验，URL/Referer/UA 输出 HTML 转义，下钻筛选条件能正确带入。

## 8. P0｜页面分析

历史统计主维度优先使用规范化 Path，默认不使用 query string 作为页面维度，完整 URL 只保留在访问详情。必须明确并测试尾斜杠及明显等价形式的归一化规则，不允许无意义参数造成页面维度膨胀。

页面列表展示 Path/标题、真人 PV/UV/IP、蜘蛛访问量、平均服务端处理耗时、4xx/5xx 次数和最近访问时间；页面详情提供真人访问趋势、来源类型分布、蜘蛛访问趋势、状态码分布和最近记录。页面聚合支持下钻。不在 2.0.0 首发提供 Session 路径、漏斗和退出页分析。

## 9. P0｜来源分析

来源分类包括直接访问、搜索引擎、外部网站、社交媒体、站内来源、其他/未识别，默认以真人访问为主。核心视图包括来源类型趋势、搜索引擎分布、外链域名排行、Referer URL 排行和着陆页排行。

关键词只在 Referer 实际携带且可解析时展示，不承诺完整关键词数据和关键词排名。站内来源不能误判为外链，Referer 为空归为直接访问，搜索引擎至少覆盖百度、Google、Bing、搜狗、360。v1.3 的 SEO 报告和来源分析统一归入本模块。高基数“来源 URL → 着陆页”组合深度分析为 P1。

## 10. P0｜蜘蛛分析

展示蜘蛛访问总量、类型数量、最近抓取时间、蜘蛛 4xx/5xx 和平均服务端处理耗时，提供蜘蛛类型分布、趋势、抓取页面排行、状态码分布和最近蜘蛛记录。

P0 以 UA 规则识别为主，至少覆盖 Googlebot、Baiduspider、bingbot、Sogou、360Spider、Bytespider、PetalBot 等已有规则；未识别蜘蛛归为 Other Bot/其他蜘蛛。0 蜘蛛数据时正常显示空状态，蜘蛛统计支持下钻且不混入默认真人 KPI。DNS 正反向真实性验证为 P1。

## 11. P0｜错误分析

提供状态码分布、404/5xx 趋势、高频错误 URL/Path、错误来源 Referer 和最近错误记录。错误列表显示 Path/URL、状态码、发生次数、首次/最近出现、最近来源和最近 UA/蜘蛛类型。

高频 404 可标记为“疑似死链”，但不得描述为完整站点爬虫式死链扫描器。404 和 5xx 可独立筛选，聚合错误项支持下钻。首发不要求独立错误原始表，除非最终性能设计证明必要。

## 12. P0｜设置与维护

采集设置包括启停采集、Referer、UA、蜘蛛、服务端处理耗时、排除路径/IP/UA、排除管理员访问、可信代理/CDN 真实 IP、IP 完整/脱敏模式及 visitor secret/隐私配置。

数据设置包括原始日志保留天数、汇总保留策略、自动/手动清理和数据量提示。升级维护包括插件版本、数据库版本、最近迁移结果、数据结构状态、最近一条访问时间、最近汇总时间、手动结构检查、汇总重建和必要的安全修复入口。

所有写操作必须 CSRF 校验；升级、汇总和结构检查可重复执行；失败必须返回失败状态；统计插件异常不能中断前台正常响应。

## 13. P0｜发布性能基础

2.0.0 发布必须具备：日级汇总、常用统计必要索引、汇总任务幂等、汇总结果可安全重建、升级后可从保留的 v1.3 原始日志构建历史汇总，以及 7/30 天常用查询不依赖无界全表扫描。容量评估至少覆盖 10 万、100 万、1000 万行原始日志。

## 14. P1｜增强能力

P1 包括：小时级汇总、高级缓存、IP 归属地、IP 地域聚合、高基数来源 URL→着陆页组合分析、CSV 导出、保存常用筛选视图、蜘蛛 DNS 正反向真实性验证、页面标题与 Z-Blog 内容 ID 关联展示。P1 不作为 2.0.0 首发硬门槛。

## 15. P2｜后续版本候选

自动封禁、黑白名单、复杂 IP 风险评分、实时安全告警、WebSocket 实时访问流、重型自动报表、外部威胁情报、完整 SEO 关键词排名、稳定 Session、跳出率/停留时长/漏斗、跨设备真实用户画像，均移出 2.0.0。

## 16. 统计口径冻结原则

- 访客 PV = `IsBot = 0` 的日志量；
- 访客 UV = `IsBot = 0` 下 `COUNT(DISTINCT VisitorHash)`；
- 访客独立 IP = `IsBot = 0` 下 `COUNT(DISTINCT IP)`；
- 蜘蛛访问量 = `IsBot = 1` 的日志量；
- 蜘蛛类型 = `BotName`；
- 状态码 = `StatusCode`；
- 服务端处理耗时 = `DurationMs`；
- 页面维度优先使用规范化 `Path`；
- 来源基于 `Referer` 分类；
- 所有时间范围统一使用 Z-Blog 站点时区。

技术设计如需改变口径，必须提交 PRD 变更记录并说明历史兼容影响。

## 17. v1.3 历史数据兼容

可历史回算：真人 PV/UV/IP、蜘蛛访问趋势、蜘蛛类型、Path 页面排行、Referer 来源、状态码/404/5xx、服务端处理耗时、浏览器/OS/Device（历史启用 UA 时）。

无法可靠回算：真实新访客/回访、Session、跳出率、停留时长、完整访问漏斗、完整关键词排名、关闭采集期间的 Referer/UA/蜘蛛、masked IP 原始值。这些能力不得通过推测补算历史数据。

## 18. 数据模型方向约束

最终技术设计必须重新评审现有 Phase 1：`xz_visit_pages` 保留“稳定页面维度 + 时间粒度汇总”方向但不沿用旧单行累计模型；`xz_visit_keywords` 旧规划删除；`xz_visit_errors` 不建立独立原始错误表；`xz_visit_security` 移出 v2.0。日汇总为 P0，小时汇总为 P1。原始日志继续负责访问明细、最近访问、蜘蛛明细、错误明细和低频自定义查询。

## 19. 安全与隐私

后台仅授权管理员访问；后台写操作必须 CSRF 防护；查询参数严格验证；URL/Referer/UA 输出 HTML 转义；SQL 不得拼接未经白名单或安全处理的用户输入；支持 IP 脱敏；masked IP 模式不得伪造精确地域；报告和日志不得暴露数据库凭据、Cookie、Token；清理、升级、汇总和修复必须明确范围和失败状态。

## 20. 兼容性

支持 Z-Blog PHP 当前稳定版本；PHP 8.0+ 为主要支持目标，当前 PHP 8.3 开发环境必须通过；兼容 Z-Blog 当前数据库层；v1.3 → v2.0 原访问数据不得丢失；升级脚本可重复执行；新安装与旧版本升级最终结构一致。

## 21. v2.0.0 发布验收

发布前至少满足：7 个 P0 模块全部完成；真人与蜘蛛口径分离；站点时区和日界线统一；主要聚合支持下钻；数据采集和新鲜度状态可见；Path 规范化稳定且有测试；日汇总、必要索引、幂等和重建机制完成；v1.3→v2.0 真实升级通过；历史记录可读并能构建历史汇总；重复升级安全；本机 Z-Blog 后台页面和数据库验证通过；PHP/PHPUnit/GitHub CI 通过；目标数据量下常用查询可接受；CHANGELOG/VERSION/Release Notes 完整；Release Dry Run 通过；Notion 最终回写完成；FULL DEVELOPMENT FLOW GATE 最终为 COMPLETE。

## 22. 需求冻结边界

本 PRD 冻结的是**产品范围和用户可见行为**，不冻结具体表名、字段名、索引实现和类结构。冻结后允许在不改变用户可见需求的前提下调整表结构、缓存、查询和任务实现，依据性能测试优化汇总粒度，以及修复缺陷、兼容性和安全问题。冻结后若要新增或删除 P0、改变统计语义或用户可见口径，必须先更新 PRD 并记录原因。

## 23. 下一阶段

需求已冻结，直接进入技术设计：统计口径技术定义 → 最终数据模型 → 日汇总/可选小时汇总 → 索引与容量设计 → Phase 1 schema/migration 返工 → 开发阶段拆分 → Phase 2 正式开发。
