# xz_visit_stats v2.0 正式 PRD v1.1

状态：**FROZEN｜需求已冻结**。本版已合并 PRD v1.0 产品评审结论，并通过最终冻结检查，作为 v2.0 正式产品需求基线。后续不再继续生成新的 PRD 版本；只有新增/删除 P0、改变统计语义或用户可见口径时才允许变更本 PRD。

产品定位：**站长访问分析中心**。

## 1. 产品目标

xz_visit_stats v2.0 面向 Z-Blog PHP 站长，将现有访问统计能力升级为用于日常运营、SEO 来源观察、蜘蛛抓取分析、错误排查和数据维护的一体化访问分析后台。

v2.0 必须帮助站长快速回答五个问题：

1. 谁来了；
2. 从哪里来；
3. 看了什么；
4. 蜘蛛抓了什么；
5. 哪里异常。

产品目标不是堆叠指标，而是让站长从“看到数据”继续走到“定位原因”。

## 2. 目标用户

- 使用 Z-Blog PHP 的个人站长和内容站维护者；
- 希望在本地掌握访问、来源、蜘蛛和错误数据的站长；
- 需要快速定位 404、5xx、异常来源、服务端慢请求和蜘蛛抓取问题的维护者；
- 不希望完全依赖外部统计平台的站点运营者。

## 3. 设计原则

- 产品需求优先；v1.3 数据用于历史兼容和可实现性校验，不作为产品需求来源。
- 默认站长主视图以**真人访问**为核心，蜘蛛访问独立展示，避免混淆流量判断。
- 历史可计算指标保持兼容；历史无法可靠回算的能力必须标记“仅升级后统计”或移出 v2.0。
- 不把 v2.0 做成 WAF、全功能 SEO 排名平台或复杂用户行为分析系统。
- 不提供无法由现有数据证明的伪精确指标。
- 所有图表和聚合分析尽量支持下钻到具体访问记录或模块详情。
- 常用查询必须具备可长期运行的数据架构，不能依赖无界全表扫描。
- 数据库、升级、Hook、采集、后台页面和汇总逻辑必须经过真实 Z-Blog 环境验证。

## 4. 后台信息架构

插件保持一个主入口“访问分析”，内部提供 7 个固定模块：

```text
访问分析
├─ 总览
├─ 访问记录
├─ 页面分析
├─ 来源分析
├─ 蜘蛛分析
├─ 错误分析
└─ 设置与维护
```

默认进入“总览”。不再新增一级菜单。

## 5. 优先级定义

- **P0**：v2.0 首发必须完成，缺失即不能发布 2.0。
- **P1**：v2.0 应完成或 2.0.x 优先补齐，不作为 2.0.0 首发硬门槛。
- **P2**：2.1 / 2.2 候选，不进入 2.0.0 首发范围。

## 6. P0｜数据总览

### 6.1 用户场景

站长进入插件后，应能立即判断今天和近期真人流量是否正常，并快速看到主要页面、来源、蜘蛛和错误情况。

### 6.2 默认主 KPI

默认主 KPI 仅统计真人访问：

- 访客 PV：`IsBot = 0` 的日志量；
- 访客 UV：`IsBot = 0` 下 `VisitorHash` 去重；
- 访客独立 IP：`IsBot = 0` 下 IP 去重；
- 4xx 数量；
- 5xx 数量；
- 平均**服务端处理耗时**。

蜘蛛访问量独立展示；“总请求量”可以作为辅助指标，但不得替代真人 PV。

### 6.3 时间范围

- 今天；
- 昨天；
- 最近 7 天；
- 最近 30 天；
- 自定义日期范围。

所有模块统一使用 Z-Blog 站点时区。今天/昨天均按站点本地 `00:00:00` 切分。

### 6.4 页面内容

- 真人 PV / UV / IP 趋势；
- 真人访问 / 蜘蛛访问趋势；
- 来源类型占比；
- 热门页面 Top N；
- 蜘蛛 Top N；
- 4xx / 5xx 错误摘要；
- 当前周期与上一周期对比；
- 当前采集状态；
- 最近一条访问数据时间；
- 最近一次汇总时间；
- 数据库或汇总异常状态。

### 6.5 下钻要求

点击趋势点、热门页面、来源、蜘蛛、4xx/5xx 等聚合项，应能进入带入时间范围和筛选条件的访问记录或对应模块详情。

### 6.6 验收标准

- 真人主 KPI 不混入蜘蛛；
- 所有指标使用一致时间边界；
- 无数据时显示 0 或空状态，不报错；
- 采集关闭、数据延迟或汇总异常时有明确提示；
- 7/30 天常用查询不能依赖无界全表扫描。

## 7. P0｜访问记录

### 7.1 用户场景

站长需要查看单次访问明细，并通过组合条件定位某个 IP、页面、蜘蛛、来源、状态码或服务端慢请求。

### 7.2 默认字段

- 访问时间；
- IP；
- 真人 / 蜘蛛；
- 蜘蛛名称；
- URL / Path；
- 来源类型；
- Referer；
- 浏览器；
- 操作系统；
- 设备类型；
- HTTP 状态码；
- 服务端处理耗时。

IP 归属地不作为 P0 硬门槛。

### 7.3 筛选条件

- 时间范围；
- IP；
- URL / Path 关键词；
- 真人 / 蜘蛛；
- 蜘蛛类型；
- 来源类型；
- 状态码 / 状态码分组；
- 浏览器 / 设备类型。

### 7.4 快速视图

- 最近 5 分钟；
- 最近 15 分钟；
- 最近 30 分钟；
- 仅蜘蛛；
- 仅错误请求；
- 服务端慢请求。

原“实时访问”和“IP 分析”不再占独立一级菜单。

### 7.5 详情

记录详情可以展示完整 URL、Referer、UA、解析结果和该 IP 的近期访问摘要。

### 7.6 验收标准

- 分页稳定；
- 多条件组合筛选正确；
- 输入参数严格校验；
- URL / Referer / UA 输出 HTML 转义；
- 列表控制信息密度，完整值放在详情；
- 从聚合页面下钻时筛选条件能够正确带入。

## 8. P0｜页面分析

### 8.1 页面聚合口径

- 历史统计主维度优先使用**规范化 Path**；
- 默认不使用 query string 作为页面维度；
- 完整 URL 保留在访问详情中；
- 必须明确并测试 `/path`、尾斜杠及明显等价形式的归一化规则；
- 不允许无意义参数造成页面维度无限膨胀。

### 8.2 页面列表

- Path / 页面标题；
- 真人 PV；
- 真人 UV；
- 真人独立 IP；
- 蜘蛛访问量；
- 平均服务端处理耗时；
- 4xx / 5xx 次数；
- 最近访问时间。

### 8.3 页面详情

- 真人访问趋势；
- 来源类型分布；
- 蜘蛛访问趋势；
- 状态码分布；
- 最近访问记录。

### 8.4 验收标准

- 页面维度稳定且可测试；
- 历史 v1.3 数据可按 Path 聚合；
- 页面聚合可以下钻到对应访问记录；
- 不在 2.0.0 首发提供 Session 路径、漏斗、退出页分析。

## 9. P0｜来源分析

### 9.1 来源分类

- 直接访问；
- 搜索引擎；
- 外部网站；
- 社交媒体；
- 站内来源；
- 其他 / 未识别。

默认来源分析以真人访问为主。

### 9.2 核心视图

- 来源类型趋势；
- 搜索引擎分布；
- 外链域名排行；
- Referer URL 排行；
- 着陆页排行。

高基数“来源 URL → 着陆页”组合深度分析调整为 P1。

### 9.3 搜索关键词

仅在 Referer 实际携带且可解析关键词时展示。v2.0 不承诺完整关键词数据，不提供关键词排名能力。

### 9.4 验收标准

- 来源分类规则稳定、可单元测试；
- 站内来源不能误判为外链；
- Referer 为空时归为直接访问；
- 搜索引擎识别至少覆盖百度、Google、Bing、搜狗、360；
- v1.3 的“SEO 报告”和“来源分析”统一归入本模块；
- 聚合项支持下钻到对应访问记录。

## 10. P0｜蜘蛛分析

### 10.1 核心指标

- 蜘蛛访问总量；
- 蜘蛛类型数量；
- 最近抓取时间；
- 蜘蛛 4xx / 5xx 数量；
- 平均服务端处理耗时。

### 10.2 核心视图

- 蜘蛛类型分布；
- 蜘蛛访问趋势；
- 蜘蛛抓取页面排行；
- 蜘蛛状态码分布；
- 最近蜘蛛记录。

### 10.3 识别范围

P0 以 UA 规则识别为主。至少覆盖 Googlebot、Baiduspider、bingbot、Sogou、360Spider、Bytespider、PetalBot 等已有规则。未识别蜘蛛归为 Other Bot / 其他蜘蛛。

DNS 正反向真实性验证调整为 P1。

### 10.4 验收标准

- 0 蜘蛛数据时正常显示空状态；
- 蜘蛛图表支持下钻到对应访问记录；
- 蜘蛛数据不计入默认真人主 KPI。

## 11. P0｜错误分析

### 11.1 核心视图

- 状态码分布；
- 404 趋势；
- 5xx 趋势；
- 高频错误 URL / Path；
- 错误来源 Referer；
- 最近错误记录。

### 11.2 错误列表

- Path / URL；
- 状态码；
- 发生次数；
- 首次出现；
- 最近出现；
- 最近来源；
- 最近 UA / 蜘蛛类型。

### 11.3 行为定义

高频 404 可以标记为“疑似死链”，但不得描述为完整站点爬虫式死链扫描器。

### 11.4 验收标准

- 404 和 5xx 可以独立筛选；
- 聚合错误项可以下钻到访问记录；
- 首发不要求独立错误原始表，除非最终性能设计证明必要。

### 12.3 升级维护

## 16. 统计口径冻结原则

### 16.1 默认真人指标

- 访客 PV = `IsBot = 0` 的日志量；
- 访客 UV = `IsBot = 0` 下 `COUNT(DISTINCT VisitorHash)`；
- 访客独立 IP = `IsBot = 0` 下 `COUNT(DISTINCT IP)`。

### 16.2 蜘蛛指标

- 蜘蛛访问量 = `IsBot = 1` 的日志量；
- 蜘蛛类型 = `BotName`；
- 蜘蛛统计独立展示，不混入真人主 KPI。

### 16.3 其他指标

- 状态码 = `StatusCode`；
- 服务端处理耗时 = `DurationMs`；
- 页面维度优先使用规范化 `Path`；
- 来源基于 `Referer` 分类；
- 所有时间范围统一使用 Z-Blog 站点时区。

技术设计如需改变口径，必须提交 PRD 变更记录并说明历史兼容影响。

## 17. v1.3 历史数据兼容

### 17.1 可历史回算

- 真人 PV / UV / IP；
- 蜘蛛访问趋势；
- 蜘蛛类型；
- Path / 页面访问排行；
- Referer 来源；
- 状态码 / 404 / 5xx；
- 服务端处理耗时；
- 浏览器 / OS / Device（历史启用 UA 时）。

### 17.2 无法可靠回算

- 真实新访客 / 回访访客；
- Session；
- 跳出率；
- 停留时长；
- 完整访问漏斗；
- 完整关键词排名；
- 关闭采集期间的 Referer / UA / 蜘蛛；
- masked IP 的原始 IP。

这些能力不得通过推测补算历史数据。

## 18. 数据模型方向约束

最终技术设计必须重新评审现有 Phase 1：

- `xz_visit_pages`：保留“稳定页面维度 + 时间粒度汇总”方向，不沿用旧单行累计模型；
- `xz_visit_keywords`：旧规划删除，只有真实性能需要时再评估；
- `xz_visit_errors`：不建立独立错误原始表，优先使用原始日志和通用汇总；
- `xz_visit_security`：移出 v2.0；
- 日汇总：P0；
- 小时汇总：P1；
- 原始日志继续负责访问明细、最近访问、蜘蛛明细、错误明细和低频自定义查询。

## 19. 安全与隐私

- 后台仅授权管理员访问；
- 所有后台写操作必须 CSRF 防护；
- 所有查询参数严格验证；
- URL / Referer / UA 输出必须 HTML 转义；
- SQL 不得直接拼接未经白名单或安全处理的用户输入；
- 支持 IP 脱敏；
- masked IP 模式下不得伪造精确地域；
- 报告和日志不得暴露数据库凭据、Cookie、Token；
- 清理、升级、汇总和修复操作必须明确范围和失败状态。

## 20. 兼容性

- 支持 Z-Blog PHP 当前稳定版本；
- PHP 8.0+ 为主要支持目标；当前 PHP 8.3 开发环境必须通过；
- 兼容 Z-Blog 当前数据库层；
- v1.3 → v2.0 原访问数据不得丢失；
- 升级脚本可重复执行；
- 新安装与旧版本升级最终结构一致。

## 22. 需求冻结边界

本 PRD 冻结的是**产品范围和用户可见行为**，不冻结具体表名、字段名、索引实现和类结构。

冻结后允许：

- 在不改变用户可见需求的前提下调整表结构、缓存、查询和任务实现；
- 依据性能测试优化汇总粒度；
- 修复缺陷、兼容性和安全问题。

冻结后若要新增或删除 P0 功能、改变统计语义、改变用户可见口径，必须先更新 PRD 并记录变更原因。
