# xz_visit_stats v2.0 PRD v1.0 产品需求评审

状态：产品评审完成，PRD 尚未冻结。

## 评审结论

当前 7 个一级模块结构合理，不建议继续增加一级菜单。v2.0 仍应保持“站长访问分析中心”定位。

本轮评审发现：现有 PRD 主体可保留，但在冻结前必须修正若干会影响数据理解、使用闭环和发布质量的问题。

## P0 必须修正

### 1. 真人访问与蜘蛛访问必须分开

当前 PRD 的 PV / UV / 独立 IP 定义沿用“全部日志”口径，容易让蜘蛛流量污染站长对真实访问的判断。

建议冻结为：

- Dashboard 默认主 KPI 为真人访问：
  - 访客 PV = `IsBot = 0` 的日志量；
  - 访客 UV = `IsBot = 0` 下 `VisitorHash` 去重；
  - 访客独立 IP = `IsBot = 0` 下 IP 去重；
- 蜘蛛访问量独立展示；
- “总请求量”可作为辅助指标，但不替代访客 PV；
- 页面分析、来源分析默认以真人访问为主；蜘蛛数据在蜘蛛模块和页面详情中单独展示。

v1.3 历史数据可以依据 `IsBot` 重新分层统计，因此不影响历史兼容。

### 2. “响应时间”统一改为“服务端处理耗时”

v1.3 的 `DurationMs` 来自服务端请求处理过程，不等价于浏览器页面加载时间、Core Web Vitals 或用户端网络耗时。

PRD 中以下文案统一修改：

- 平均响应时间 → 平均服务端处理耗时；
- 慢请求 → 服务端慢请求；
- 页面性能相关文案必须明确“服务端”，禁止让用户误认为是前端加载性能。

### 3. 统一站点时区与统计日界线

今天、昨天、7 天、30 天、自定义时间范围必须以 Z-Blog 当前站点时区为唯一口径。

P0 验收增加：

- 所有模块使用相同站点时区；
- 今天/昨天按站点本地 00:00:00 切分；
- 趋势图、汇总表、原始日志查询使用一致时间边界；
- 升级前后不能因为服务器系统时区不同造成日期错位。

### 4. Dashboard 与聚合分析必须支持下钻

站长看到异常后必须能继续定位原因，不能停留在图表层。

P0 要求：

- 点击 4xx/5xx、蜘蛛、来源、热门页面、趋势点等可进入对应筛选后的访问记录或模块详情；
- 下钻时自动带入时间范围和筛选条件；
- 返回上级页面时尽量保留筛选状态。

### 5. 增加“数据新鲜度 / 采集状态”

总览或设置维护必须明确显示：

- 最近一条访问数据时间；
- 当前采集是否启用；
- 最近一次汇总时间（启用汇总后）；
- 数据库/汇总异常时给出明确状态。

避免出现“统计为 0，但站长不知道是没人访问还是插件没采到”的情况。

### 6. 页面聚合必须固定 URL 规范化规则

页面分析 P0 冻结为：

- 历史聚合主键优先使用规范化 Path；
- 页面统计默认不使用 query string 作为页面维度；
- 完整 URL 继续保留在访问详情；
- `/path` 与明显等价形式的归一化规则必须明确并可测试；
- 不允许无意义参数造成页面维度无限膨胀。

### 7. 性能基线的一部分从 P1 提升为 P0

以下属于 2.0 可发布的基础条件，不应允许延后到 2.0.x：

- 日级汇总；
- 常用统计必要索引；
- 汇总任务幂等；
- 汇总结果可安全重建；
- 升级后可从保留的 v1.3 原始日志构建历史汇总；
- 7 天 / 30 天常用查询在目标数据量下不得依赖无界全表扫描。

小时级汇总和高级缓存仍可保留 P1。

## P0 保持不变

以下模块保持 P0：

- 总览；
- 访问记录；
- 页面分析；
- 来源分析；
- 蜘蛛分析；
- 错误分析；
- 设置与维护。

不新增新的一级模块。

## 建议从 P0 降为 P1 / 条件能力

### IP 归属地

IP 归属地依赖可靠 IP 数据库或外部服务，不应成为 2.0 发布硬门槛。

调整为 P1：

- 有可靠本地数据源时展示；
- 无数据源时隐藏，不影响访问记录主体功能；
- masked IP 模式下不得伪造精确地域。

### 来源 → 着陆页组合深度分析

基础来源分类、搜索引擎、外链域名、着陆页继续 P0。

高基数“来源 URL → 着陆页”组合分析建议调整为 P1，以免在首版造成过高查询和 UI 复杂度。

## 建议新增 P1

### 数据导出

- 当前筛选结果导出 CSV；
- 导出必须遵守权限、脱敏与记录范围；
- 大数据量导出必须有数量限制或分批机制。

### 保存筛选视图

- 可保存常用筛选，例如“仅百度蜘蛛”“最近 404”“服务端慢请求”；
- 不作为首发硬门槛。

### IP 地域分析

在有可靠数据源时提供国家/省市级聚合，必须与隐私模式兼容。

### 蜘蛛真实性验证

DNS 正反向校验等真实性验证放 P1，不影响 P0 的 UA 识别能力。

## P2 继续后移

保持后移：

- 自动封禁；
- 黑白名单联动；
- 复杂风险评分；
- 实时安全告警；
- WebSocket 实时访问流；
- 重型自动报表；
- 外部威胁情报；
- 完整 SEO 关键词排名；
- 稳定 Session；
- 跳出率 / 停留时长 / 漏斗；
- 跨设备真实用户画像。

## 推荐冻结后的 P0 定义

v2.0 首发的 P0 不只是“7 个页面做出来”，而应同时满足：

1. 真人访问与蜘蛛口径分离；
2. 7 个业务模块完成；
3. 指标时区和统计日界线一致；
4. 主要聚合支持下钻；
5. 有数据采集/新鲜度状态；
6. 页面维度 URL 规范化稳定；
7. 日汇总、必要索引、重建机制完成；
8. v1.3 → v2.0 历史数据可继续使用；
9. 本机 Z-Blog 真实升级、页面、数据库和 CI 验证通过。

## 评审结果

- 产品定位：通过；
- 7 个一级模块：通过；
- P0/P1/P2：需要按本评审调整后再冻结；
- v1.3 兼容原则：通过；
- 数据指标语义：需要修订；
- 性能优先级：需要修订；
- PRD 状态：继续评审，不进入正式 Phase 2 开发。
