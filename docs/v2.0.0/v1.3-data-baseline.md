# xz_visit_stats v2.0｜v1.3 数据基线

状态：需求设计基线，正式 PRD 冻结前必须引用。

## 核心原则

v2.0 的统计口径、汇总表、迁移方案和历史数据兼容必须以 v1.3 的真实已有数据为基础，不允许根据理想模型凭空设计指标。

数据基线分两层：

1. 代码/结构基线：以 v1.3 当前真实采集代码、表结构和查询口径为准；
2. 实际数据基线：以本机 v1.3 数据库中已积累的真实访问日志分布为准。

正式冻结 v2.0 数据模型前，两层都必须完成。

## v1.3 原始访问表

现有主表：`%pre%xz_visit_stats_log`。

真实字段：

- `vs_ID`
- `vs_IP`
- `vs_VisitorHash`
- `vs_Url`
- `vs_Path`
- `vs_Referer`
- `vs_UserAgent`
- `vs_UaType`
- `vs_Browser`
- `vs_Os`
- `vs_Device`
- `vs_IsBot`
- `vs_BotName`
- `vs_StatusCode`
- `vs_DurationMs`
- `vs_VisitedAt`

v2.0 设计优先复用这些字段，不为已经存在的数据重复建立原始事件表。

## v1.3 已有统计口径

- PV：时间范围内访问日志行数。
- UV：`COUNT(DISTINCT vs_VisitorHash)`。
- 独立 IP：`COUNT(DISTINCT vs_IP)`。
- 蜘蛛访问：`vs_IsBot = 1`。
- 蜘蛛分类：`vs_BotName`。
- 2xx/3xx/4xx/5xx/404：基于 `vs_StatusCode`。
- 平均响应时间：`AVG(vs_DurationMs)`。
- 页面/路径：基于 `vs_Path` / `vs_Url`。
- 来源分类：基于 `vs_Referer` 在查询阶段解析。
- 搜索引擎/关键词：仅在 Referer 实际携带且可解析时得到。
- 设备/浏览器/系统：基于采集时 UA 解析结果。

除非正式 PRD 明确变更统计定义并提供兼容说明，v2.0 不应悄悄改变这些历史口径。

## 数据完整性限制

v1.3 配置会影响历史数据完整性，因此 v2.0 页面必须承认这些限制：

- `record_referer=0` 时历史 Referer 为空，不能补算来源。
- `record_user_agent=0` 时 UA、浏览器、OS、设备字段为空。
- 蜘蛛可按总开关和具体蜘蛛类型关闭采集，被关闭期间无法补回历史蜘蛛数据。
- `ip_mode=masked` 时存储的是脱敏 IP，独立 IP/IP 详情精度会下降。
- `VisitorHash` 是 IP + User-Agent + 站点 secret 的 HMAC，不等价于真实用户账号或稳定跨设备身份。
- 原始表没有稳定 Session ID，因此跳出率、会话时长、跨页路径不能从历史 v1.3 数据可靠还原。
- 原始表没有独立的历史页面标题字段；历史页面标题不能假设始终可从当前站点状态准确回填。

## v2.0 可以直接从 v1.3 历史数据得到的能力

- PV / UV / 独立 IP 及趋势
- 人类 / 蜘蛛访问趋势
- 蜘蛛类型与抓取 Path
- 状态码、404、5xx、错误 URL
- 响应耗时和慢请求分析
- 页面/Path 访问排行
- Referer 来源类型、域名、完整 URL（前提是当时启用了 Referer）
- 搜索引擎来源与少量可解析关键词
- 浏览器 / OS / 设备分布（前提是当时启用了 UA）
- IP 访问频率、404 比例、可疑 UA 等基于日志的行为分析

## 不能仅靠 v1.3 历史数据可靠得到的能力

- 真实“新访客 / 回访访客”
- 用户账号级行为画像
- 稳定 Session
- 精确跳出率 / 会话时长 / 访问漏斗
- 搜索关键词排名
- 被关闭采集期间的 Referer / UA / 蜘蛛数据
- 已脱敏 IP 的完整原 IP

这些能力若未来需要，必须新增采集机制并明确“仅从升级后开始统计”，不得伪装成可回溯历史数据。

## 本机真实数据画像：冻结前硬门槛

Codex 工作区在冻结 v2.0 数据模型前，必须以只读方式分析本机现有 v1.3 数据库，至少输出：

- 总日志行数；
- 最早/最新访问时间；
- 按天日志量分布；
- `vs_VisitorHash`、`vs_IP`、`vs_Path` 基数；
- Referer 空值率；
- UserAgent/Browser/OS/Device 空值率；
- 蜘蛛占比和主要 `BotName`；
- 2xx/3xx/4xx/5xx/404 分布；
- `vs_DurationMs=0` 比例、P50/P95/P99 或可实现的近似分位；
- full/masked IP 的实际情况；
- Top Path/Referer 域名的基数与长尾情况；
- 表总大小和关键索引情况。

该分析必须只读，不修改现有数据。

## 对 Phase 1 的约束

现有 Phase 1 数据库架构和迁移方案是在旧的 Smart Analytics 范围下形成，包含 `xz_visit_keywords`、`xz_visit_security` 等旧规划。

在“站长访问分析中心”定位和本数据基线冻结后，必须重新评审：

- 哪些表真正需要；
- 哪些数据可以从现有原始日志按需计算；
- 哪些需要日/小时级汇总表；
- 是否需要单独错误表、关键词表；
- 页面汇总表的主键应使用 Path、规范化 URL 还是 Z-Blog 内容 ID；
- 如何避免为同一事实重复存储多份数据。

Phase 1 现有实现不能直接视为最终 v2.0 数据模型。

## 数据模型冻结条件

只有在以下三项都完成后，才允许冻结 v2.0 数据模型：

1. v1.3 真实代码/表结构基线已确认；
2. 本机 v1.3 真实数据画像已执行并记录；
3. Phase 1 现有 schema/迁移设计已按上述证据重新评审。
