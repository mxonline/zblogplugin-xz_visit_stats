# xz_visit_stats v2.0 产品定位

## 正式定位

**站长访问分析中心**

v2.0 不再只是访问次数统计插件，而是面向站长日常运营、SEO观察、蜘蛛分析和站点排障的一体化访问分析后台。

## 需要回答的核心问题

1. 谁来了：访客、IP、设备、浏览器、系统、蜘蛛。
2. 从哪来：直接访问、搜索引擎、外部链接、社交/其他来源。
3. 看了什么：页面 PV/UV、热门页面、着陆页、访问路径与时段趋势。
4. 蜘蛛抓了什么：蜘蛛类型、抓取趋势、抓取页面、最近访问。
5. 哪里异常：404/状态码异常、异常请求趋势、数据采集或升级异常。

## v2.0 核心范围

优先建设：

- 访问总览 Dashboard
- 访问明细与筛选
- 页面分析
- 来源分析
- 蜘蛛分析
- 状态码 / 错误分析
- 数据保留、清理、升级与性能设置

## 非 2.0 核心范围

以下能力不作为 v2.0 首发核心，优先放到 2.1 / 2.2：

- 自动封禁与复杂 IP 风控
- 实时安全告警
- 重型自动报表
- WebSocket 实时访问流
- 复杂 SEO 关键词排名系统
- 与外部威胁情报平台深度联动

## 产品原则

- 站长一眼能看懂，不做纯参数堆砌。
- 数据必须能支持实际判断和排障。
- 优先使用现有访问日志与增量汇总，控制前台采集开销。
- v2.0 的统计口径、数据模型和迁移必须依据 v1.3 真实已有数据；正式冻结前必须同时完成代码/结构基线和本机真实数据画像。
- 不为 v1.3 已有事实数据重复建立原始事件表；新增表优先用于真正需要的汇总、索引或升级状态。
- 大版本、数据库、Hook、后台运行时相关功能必须经过本机 Z-Blog 实机验证。
- 现有 Phase 1 升级底座保留，但必须按 `v1.3-data-baseline.md` 和本机真实数据画像重新评审后才能继续 Phase 2。

## 数据基线

正式基线文档：`docs/v2.0.0/v1.3-data-baseline.md`。

任何不能从 v1.3 历史数据可靠得到的指标，都必须明确标注“仅升级后统计”或移出 2.0，不能通过推测补算历史数据。

## 当前阶段

进入 v2.0 正式 PRD 收敛与功能边界冻结阶段。下一步先完成 v1.3 真实数据画像与统计口径设计，再冻结最终数据模型并继续 Phase 2 开发。
