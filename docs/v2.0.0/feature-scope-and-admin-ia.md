# xz_visit_stats v2.0 功能范围与后台信息架构

状态：需求设计 v0.1，尚未最终冻结。

产品定位：站长访问分析中心。

## 设计目标

v2.0 的后台需要帮助站长快速回答五个问题：谁来了、从哪来、看了什么、蜘蛛抓了什么、哪里异常。

设计原则：

- 不把 2.0 做成 WAF、全功能 SEO 平台或复杂行为分析系统；
- 优先站长高频判断与排障场景；
- 指标名称必须与真实数据能力一致，不制造“精确用户画像”的错觉；
- 复用现有 v1.3 能力，能归并就不重复建一级页面；
- 后台一级结构尽量稳定，为后续 2.1/2.2 扩展留位置。

## 一级后台结构

建议插件后台保持一个主入口“访问分析”，内部使用固定二级导航，不在 Z-Blog 左侧堆叠大量菜单。

```text
访问分析
├─ 总览
├─ 访问记录
├─ 页面分析
├─ 来源分析
├─ 蜘蛛分析
├─ 错误分析
└─ 设置与维护
```

推荐默认进入“总览”。

---

## 总览

### 页面目的

让站长在一个页面判断今天/近期流量是否正常，以及主要流量、蜘蛛和异常来自哪里。

### 核心指标卡

- PV
- UV
- 独立 IP
- 蜘蛛访问量
- 4xx/5xx 错误量
- 平均响应时间

### 时间范围

- 今天
- 昨天
- 近 7 天
- 近 30 天
- 自定义日期范围

### 图表与摘要

- PV / UV / IP 趋势
- 人类访问 / 蜘蛛访问趋势
- 来源类型占比：直接访问、搜索引擎、外部链接、其他
- 热门页面 Top N
- 蜘蛛类型 Top N
- 错误状态码 / 错误 URL 摘要

### 明确不做

- 不把“新访客 / 回访访客”作为 2.0 核心 KPI。现有 visitor hash 不能可靠等价于真实用户身份。
- 不展示跳出率、退出率、会话时长等需要稳定 sessionization 才能成立的指标。

## 访问记录

### 页面目的

查看单次访问明细，并通过筛选快速定位具体访客、页面、来源、蜘蛛和错误请求。

### 默认字段

- 访问时间
- IP
- IP 归属地（有数据时）
- 人类 / 蜘蛛
- 蜘蛛名称（如适用）
- 页面标题 / URL
- 来源类型
- Referer 域名 / URL
- 浏览器
- 操作系统
- 设备类型
- HTTP 状态码
- 响应耗时

### 核心筛选

- 时间范围
- IP
- URL / 页面关键词
- 人类 / 蜘蛛
- 蜘蛛类型
- 来源类型
- 状态码
- 设备类型

### 快速视图

- 最近 5 分钟
- 最近 15 分钟
- 最近 30 分钟
- 仅蜘蛛
- 仅错误请求
- 慢请求

“实时访问”并入这些最近时间视图，不再单独占一级菜单。

### 详情能力

点击一条记录可查看完整 UA、完整 Referer、完整 URL、解析结果及该 IP 的近期访问摘要。

## 页面分析

### 页面目的

回答“哪些内容真正带来访问，以及哪些页面存在明显性能或错误问题”。

### 核心指标

- 页面 PV
- 页面 UV
- 独立 IP
- 最近访问时间
- 平均响应时间
- 4xx/5xx 次数

### 页面列表

- 页面标题
- URL / Path
- PV
- UV
- IP
- 平均响应时间
- 最近访问
- 错误次数

### 页面详情

- 访问趋势
- 来源类型分布
- 蜘蛛访问趋势
- 状态码分布
- 最近访问记录

### 明确不做

- 2.0 不做完整用户访问路径、漏斗、退出页、跨页 session 分析。

---

## 来源分析

### 页面目的

回答“流量从哪里来，哪些搜索引擎、外链和入口页真正带来访问”。

### 来源分类

- 直接访问
- 搜索引擎
- 外部链接
- 站内跳转
- 其他 / 未识别

### 核心视图

- 来源类型趋势
- 搜索引擎分布
- 外链域名排行
- Referer URL 排行
- 着陆页排行
- 来源 → 着陆页组合

### 搜索关键词

仅在 Referer 实际包含可解析关键词时记录和展示。

现代搜索引擎大量隐藏关键词，因此 2.0 不承诺“完整搜索关键词”或“关键词排名”能力。

### 旧功能归并

v1.3 的“SEO 报告”和“来源分析”统一归入本模块，避免两个页面展示高度重复的数据。

---

## 蜘蛛分析

### 页面目的

回答“哪些搜索蜘蛛来过、什么时候来、抓了哪些页面、抓取结果是否异常”。

### 核心指标

- 蜘蛛访问总量
- 蜘蛛类型数量
- 最近抓取时间
- 蜘蛛 4xx/5xx 数量

### 核心视图

- 蜘蛛类型分布
- 蜘蛛访问趋势
- 蜘蛛抓取页面排行
- 蜘蛛状态码分布
- 各蜘蛛最近访问记录

### 详情字段

- 蜘蛛名称
- IP
- UA
- 抓取 URL
- 状态码
- 时间
- 响应耗时

### 2.0 边界

- 首发以 UA 规则识别为主；
- DNS 反查验证、复杂伪装蜘蛛识别、威胁情报联动放到后续版本评估。

---

## 错误分析

### 页面目的

让站长快速找到高频 404、5xx、异常 URL 和错误来源。

### 核心视图

- 状态码分布
- 404 趋势
- 5xx 趋势
- 高频错误 URL
- 错误来源 Referer
- 最近错误记录

### 错误 URL 列表

- URL
- 状态码
- 发生次数
- 首次出现
- 最近出现
- 最近 Referer
- 最近 UA / 蜘蛛类型

### 说明

2.0 可把高频 404 作为“疑似死链”提示，但不把它描述成完整站点爬虫式死链扫描器。

---

## 设置与维护

### 采集设置

- 是否启用访问采集
- 是否记录 Referer
- 是否记录 UA
- 是否记录响应耗时
- 排除路径 / IP / UA 规则
- 可信代理 / CDN IP 头配置
- Visitor salt / 隐私相关配置

### 数据设置

- 原始访问日志保留天数
- 汇总数据保留策略
- 自动清理开关
- 手动清理

### 性能设置

- 汇总任务频率
- 大数据量模式 / 性能模式
- 统计缓存刷新策略

### 升级与维护

- 当前插件版本
- 当前数据库版本
- 最近迁移结果
- 数据表状态
- 手动执行结构检查
- 必要时提供修复入口

## v1.3 现有功能迁移映射

| v1.3 能力 | v2.0 归属 |
| --- | --- |
| 统计概览 | 总览 |
| 访问记录 | 访问记录 |
| 实时访问 | 访问记录的最近时间视图 |
| IP 分析 | 访问记录 / IP 详情 |
| SEO 报告 | 来源分析 |
| 来源分析 | 来源分析 |
| 蜘蛛分析 | 蜘蛛分析 |
| 设置 | 设置与维护 |
| 页面级统计 | 页面分析 |
| 状态码 / 404 | 错误分析 |

迁移原则：优先保留已有能力和历史数据，不为了新菜单结构删除成熟功能。

---

## 明确移出 v2.0 首发的能力

优先放到 2.1 / 2.2：

- 自动封禁
- 黑白名单联动
- 复杂 IP 风险评分
- 实时安全告警
- WebSocket 实时访问流
- 重型自动报表
- 外部威胁情报平台联动
- 完整 SEO 关键词排名系统
- 完整 session 路径 / 漏斗 / 跳出率体系
