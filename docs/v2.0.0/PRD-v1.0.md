# xz_visit_stats v2.0 正式 PRD v1.0

状态：需求设计稿 v1.0，进入需求评审；尚未冻结开发范围。

产品定位：**站长访问分析中心**。

## 1. 产品目标

xz_visit_stats v2.0 面向 Z-Blog 站长，将现有访问统计能力升级为可用于日常运营、SEO 来源观察、蜘蛛抓取分析和站点错误排查的统一后台。

v2.0 需要帮助站长持续回答五个问题：

1. 谁来了；
2. 从哪里来；
3. 看了什么；
4. 蜘蛛抓了什么；
5. 哪里异常。

v2.0 不以“堆更多统计字段”为目标，而以“让站长快速看懂并采取行动”为目标。

## 2. 目标用户

- 使用 Z-Blog PHP 的个人站长；
- 需要查看真实访问、来源、蜘蛛和错误情况的内容站站长；
- 不希望依赖外部统计平台或需要本地可控访问数据的站长；
- 需要通过后台快速排查 404、慢请求、异常访问来源和蜘蛛抓取情况的维护者。

## 3. 设计原则

- 产品需求优先，v1.3 数据作为兼容性和可实现性约束，不让旧数据库反向限制产品定义。
- 优先复用 v1.3 已有访问日志和成熟能力。
- 历史数据可计算的指标必须保持口径一致；无法从历史数据可靠得到的指标必须明确“仅升级后统计”或移出 2.0。
- 不把 v2.0 做成 WAF、全功能 SEO 排名平台或复杂用户行为分析系统。
- 不提供无法被现有数据证明的伪精确指标。
- 大数据量场景优先通过汇总、索引和缓存降低原始日志扫描压力。
- 数据库、升级、Hook、采集和后台运行时相关功能必须经过真实 Z-Blog 环境验证。

## 4. 后台信息架构

插件保持一个主入口“访问分析”，内部提供 7 个固定模块：

```text
访问分析
├─ 总览
├─ 访问记录
├─ 页面分析
├─ 来源分析
├─ 蜘蛛分析
├─ 错误分析
└─ 设置与维护
```

默认进入“总览”。

## 5. 优先级定义

- P0：v2.0 首发必须完成，缺失即不能发布 2.0。
- P1：v2.0 应完成，若技术成本明显超预期可延后至 2.0.x。
- P2：增强能力，优先进入 2.1 / 2.2。

## 6. P0｜数据总览

### 用户场景

站长进入插件后台后，希望在一个页面判断今天及近期流量是否正常，并快速知道主要页面、主要来源、蜘蛛和错误情况。

### 核心指标

- PV；
- UV；
- 独立 IP；
- 蜘蛛访问量；
- 4xx 数量；
- 5xx 数量；
- 平均响应时间。

### 时间范围

- 今天；
- 昨天；
- 最近 7 天；
- 最近 30 天；
- 自定义日期范围。

### 页面内容

- PV / UV / IP 趋势；
- 人类访问 / 蜘蛛访问趋势；
- 来源类型占比；
- 热门页面 Top N；
- 蜘蛛 Top N；
- 4xx / 5xx 错误摘要；
- 今日与昨日或当前周期与上一周期对比。

### v1.3 兼容

PV、UV、IP、蜘蛛、状态码、平均响应时间和趋势均可基于 v1.3 原始日志计算。

### 验收标准

- 所有指标受同一时间范围控制；
- 当前周期和对比周期口径一致；
- 无数据时显示 0 / 空状态，不报错；
- 10 万级以上日志量时常用 7/30 天查询不能依赖无界全表扫描。

## 7. P0｜访问记录

### 用户场景

站长需要查看具体访问明细，并通过条件筛选定位某个 IP、页面、蜘蛛、状态码或来源。

### 默认字段

- 访问时间；
- IP；
- IP 归属地（仅在有可靠数据源时展示）；
- 普通访客 / 蜘蛛；
- 蜘蛛名称；
- URL / Path；
- 来源类型；
- Referer；
- 浏览器；
- 操作系统；
- 设备类型；
- HTTP 状态码；
- 响应耗时。

### 筛选条件

- 时间范围；
- IP；
- URL / Path 关键词；
- 普通访客 / 蜘蛛；
- 蜘蛛类型；
- 来源类型；
- 状态码 / 状态码分组；
- 浏览器 / 设备类型。

### 快速视图

- 最近 5 分钟；
- 最近 15 分钟；
- 最近 30 分钟；
- 仅蜘蛛；
- 仅错误请求；
- 慢请求。

### 详情

点击记录后可查看完整 URL、Referer、UA、解析结果和该 IP 的近期访问摘要。

### 验收标准

- 分页稳定；
- 多条件组合筛选结果正确；
- 所有用户输入均经过安全过滤；
- 完整 URL / UA / Referer 只在详情中展示，列表避免过度拥挤；
- 原“实时访问”和“IP 分析”不再占独立一级菜单。

## 8. P0｜页面分析

### 用户场景

站长希望知道哪些页面带来最多访问、哪些页面响应慢、哪些页面错误多，以及蜘蛛是否持续抓取。

### 页面列表

- Path / 页面标题；
- PV；
- UV；
- 独立 IP；
- 平均响应时间；
- 4xx / 5xx 次数；
- 最近访问时间。

### 页面详情

- 访问趋势；
- 来源类型分布；
- 蜘蛛访问趋势；
- 状态码分布；
- 最近访问记录。

### 验收标准

- 页面维度必须有稳定键；
- 页面统计不能因为 URL query string 的无意义变化无限拆分；
- 历史 v1.3 数据可按 Path 聚合；
- 不在 v2.0 首发提供跨页面 Session 路径、漏斗、退出页分析。

## 9. P0｜来源分析

### 用户场景

站长希望知道访问从哪里来，并判断搜索引擎、外部网站、社交来源和直接访问的占比与趋势。

### 来源分类

- 直接访问；
- 搜索引擎；
- 外部网站；
- 社交媒体；
- 站内来源；
- 其他 / 未识别。

### 核心视图

- 来源类型趋势；
- 搜索引擎分布；
- 外链域名排行；
- Referer URL 排行；
- 着陆页排行；
- 来源 → 着陆页组合。

### 搜索关键词

仅在 Referer 实际携带并可解析关键词时展示。v2.0 不承诺完整关键词数据，不提供“关键词排名”概念。

### 验收标准

- 来源分类规则稳定并可测试；
- 站内来源不会被误判为外链；
- Referer 为空时归为直接访问；
- 搜索引擎域名识别至少覆盖百度、Google、Bing、搜狗、360；
- v1.3 的“SEO 报告”和“来源分析”统一归并到本模块。

## 10. P0｜蜘蛛分析

### 用户场景

站长希望知道搜索引擎蜘蛛是否访问过站点、抓了哪些页面、访问是否正常、是否出现大量 404 或 5xx。

### 核心指标

- 蜘蛛访问总量；
- 蜘蛛类型数量；
- 最近抓取时间；
- 蜘蛛 4xx / 5xx 数量；
- 平均响应时间。

### 核心视图

- 蜘蛛类型分布；
- 蜘蛛访问趋势；
- 蜘蛛抓取页面排行；
- 蜘蛛状态码分布；
- 最近蜘蛛记录。

### 识别范围

2.0 首发以 UA 规则识别为主。DNS 反查验证、伪装蜘蛛识别和外部威胁情报不进入 P0。

### 验收标准

- 至少覆盖 Googlebot、Baiduspider、bingbot、Sogou、360Spider、Bytespider、PetalBot 等已有规则；
- 未识别蜘蛛统一归类为 Other Bot / 其他蜘蛛；
- 0 蜘蛛数据时页面正常显示空状态。

## 11. P0｜错误分析

### 用户场景

站长需要快速发现高频 404、5xx、异常 URL 以及这些错误的来源。

### 核心视图

- 状态码分布；
- 404 趋势；
- 5xx 趋势；
- 高频错误 URL；
- 错误来源 Referer；
- 最近错误记录。

### 错误 URL 列表

- Path / URL；
- 状态码；
- 发生次数；
- 首次出现；
- 最近出现；
- 最近来源；
- 最近 UA / 蜘蛛类型。

### 行为定义

高频 404 可标记为“疑似死链”，但不得描述为完整站点爬虫式死链扫描器。

### 验收标准

- 404 和 5xx 可独立筛选；
- 能从聚合项跳转到对应访问记录；
- 不要求独立错误原始表，除非最终性能设计证明必要。

## 12. P0｜设置与维护

### 采集设置

- 启用 / 停用访问采集；
- 是否记录 Referer；
- 是否记录 UA；
- 是否记录蜘蛛；
- 是否记录响应耗时；
- 排除路径 / IP / UA；
- 排除管理员访问；
- 可信代理 / CDN 真实 IP 配置；
- IP 完整 / 脱敏模式；
- visitor secret / 隐私配置。

### 数据设置

- 原始日志保留天数；
- 汇总数据保留策略；
- 自动清理；
- 手动清理；
- 数据量提示。

### 升级维护

- 插件版本；
- 数据库版本；
- 最近迁移结果；
- 结构状态；
- 手动结构检查；
- 必要时提供安全修复入口。

### 验收标准

- 所有写操作通过 CSRF 校验；
- 升级和结构检查可重复执行；
- 失败必须返回失败状态，不得标记为成功；
- 不因统计插件错误中断前台正常响应。

## 13. P1｜性能与大数据量优化

P1 不增加新的业务模块，主要保证 P0 在长期数据量下可用。

需求：

- 小时级汇总；
- 日级汇总；
- 常用时间范围优先查询汇总数据；
- 原始日志保留访问详情和低频自定义分析；
- 必要索引自动检测与补齐；
- 汇总任务具备幂等性；
- 汇总结果可以安全重建。

容量设计至少按 10 万、100 万、1000 万行原始日志评估。

## 14. P1｜页面标题与内容关联

站内 Path 可以在当前内容仍存在时关联 Z-Blog 文章 / 页面标题和内容 ID。

要求：

- 历史原始日志不能因为当前文章标题变化而被改写；
- 标题属于展示增强，不作为历史统计主键；
- 无法匹配内容时退回 Path 展示。

## 15. P2｜后续版本候选

以下功能不进入 v2.0 首发：

- 自动封禁；
- 黑白名单联动；
- 复杂 IP 风险评分；
- 实时安全告警；
- WebSocket 实时访问流；
- 重型自动报表；
- 外部威胁情报平台联动；
- 完整 SEO 关键词排名系统；
- 稳定 Session 行为分析；
- 跳出率 / 停留时长 / 漏斗；
- 跨设备真实用户画像。

优先进入 2.1 / 2.2 评估。

## 16. 统计口径约束

默认保持 v1.3 现有定义：

- PV = 时间范围内访问日志行数；
- UV = COUNT(DISTINCT VisitorHash)；
- 独立 IP = COUNT(DISTINCT IP)；
- 蜘蛛 = IsBot = 1；
- 状态码 = StatusCode；
- 平均响应时间 = AVG(DurationMs)；
- 页面维度优先使用 Path；
- 来源基于 Referer 分类。

如果后续技术设计需要改变任何口径，必须在 PRD 变更记录中说明影响和历史兼容方案。

## 17. v1.3 历史数据兼容

### 可直接回算

- PV / UV / IP；
- 人类 / 蜘蛛趋势；
- 蜘蛛类型；
- Path / 页面访问排行；
- Referer 来源；
- 状态码 / 404 / 5xx；
- 响应耗时；
- 浏览器 / OS / Device（历史启用 UA 时）。

### 无法可靠回算

- 真实新访客 / 回访访客；
- Session；
- 跳出率；
- 停留时长；
- 完整访问漏斗；
- 完整关键词排名；
- 被关闭采集期间的 Referer / UA / 蜘蛛；
- masked IP 的原始 IP。

## 18. 数据模型方向约束

最终技术设计前，现有 Phase 1 旧表规划必须按本 PRD 重评：

- `xz_visit_pages`：保留“页面维度 + 时间粒度汇总”方向，但不沿用单行累计模型；
- `xz_visit_keywords`：旧规划删除，只有在实际查询性能证明必要时再考虑独立汇总；
- `xz_visit_errors`：不建立独立原始错误表，优先用日志 / 通用汇总；
- `xz_visit_security`：移出 2.0；
- 小时汇总：需要；
- 日汇总：需要，优先级高于小时汇总；
- 原始日志继续负责访问明细、最近访问、蜘蛛明细、错误明细和低频自定义查询。

## 19. 安全与隐私要求

- 后台仅授权管理员访问；
- 所有后台写操作必须 CSRF 防护；
- 所有查询参数严格验证；
- URL / Referer / UA 输出必须 HTML 转义；
- SQL 查询不得直接拼接未经白名单或转义的用户输入；
- 提供 IP 脱敏模式；
- 报告和日志不得暴露数据库凭据、Cookie、Token；
- 数据清理和升级操作必须明确范围并支持失败状态。

## 20. 兼容性要求

- Z-Blog PHP 当前稳定版本；
- PHP 8.0+ 为主要支持目标，当前开发环境 PHP 8.3 必须通过；
- MySQL / Z-Blog 当前数据库层兼容；
- v1.3 → v2.0 原访问数据不得丢失；
- 升级脚本可重复执行；
- 新安装和旧版本升级最终结构一致。

## 21. 发布验收

v2.0 发布前至少满足：

- 7 个 P0 模块均完成；
- v1.3 → v2.0 真实数据库升级通过；
- 原历史访问记录可正常读取；
- 重复升级不会重复创建或破坏结构；
- 本机真实 Z-Blog 后台页面验证通过；
- PHP / PHPUnit / CI 通过；
- 常用查询在目标数据量下无明显不可接受性能问题；
- CHANGELOG / VERSION / Release Notes 完整；
- GitHub Release Dry Run 通过；
- Notion 最终回写完成。

完整开发流程仍受 FULL DEVELOPMENT FLOW GATE 约束。
