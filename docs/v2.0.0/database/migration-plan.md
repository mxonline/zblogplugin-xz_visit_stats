# xz_visit_stats v2.0.0 数据库迁移设计方案

## 目标

v2.0 在保持 v1.3 数据兼容的基础上扩展分析能力，不直接重构旧访问记录表，采用增量数据库升级方式。

升级原则：

- 不删除旧表
- 不破坏已有访问数据
- 升级过程可重复执行
- 支持失败回滚
- 新安装与旧版本升级使用同一套结构检查逻辑

---

# 当前 v1.3 架构分析

现有功能模块：

- 访问记录
- 统计概览
- 蜘蛛分析
- SEO报告
- 来源分析
- IP分析
- 实时访问
- 设置管理

v2.0 在现有采集基础上增加分析层。

---

# 新增数据表

## xz_visit_pages

用途：页面级访问统计。

字段规划：

```sql
id
url
title
pv
uv
first_visit
last_visit
updated
```

用途：

- 热门页面排行
- 内容流量分析
- 页面趋势统计

---

## xz_visit_keywords

用途：搜索关键词分析。

字段规划：

```sql
id
engine
keyword
referer_url
landing_url
count
updated
```

用途：

- 搜索来源分析
- SEO关键词统计
- 着陆页分析

---

## xz_visit_errors

用途：错误页面分析。

字段规划：

```sql
id
url
status
referer
ua
created
```

用途：

- 404分析
- 500错误分析
- 死链发现

---

## xz_visit_security

用途：访问风险分析。

字段规划：

```sql
id
ip
ua
requests
risk_level
blocked
updated
```

用途：

- 高频访问检测
- 异常UA分析
- IP风险管理

# 升级流程

## Step 1

检测当前插件版本。

示例：

```
1.3.0
↓
2.0.0
```

---

## Step 2

检查新增表是否存在。

存在：跳过。

不存在：创建。

---

## Step 3

初始化默认配置。

包括：

- 数据保留周期
- 统计开关
- 性能模式

---

## Step 4

执行兼容测试。

检查：

- 原访问记录正常
- 后台页面正常
- 新统计数据正常写入

---

# 性能要求

v2.0 不允许每次访问产生大量数据库写入。

优化方向：

- 批量统计
- 延迟汇总
- 缓存计算结果
- 定时任务更新

---

# Codex开发约束

开发数据库升级时：

1. 先读取真实 v1.3 数据结构。
2. 不根据文档猜测旧表字段。
3. 修改前生成迁移方案。
4. 所有数据库操作增加重复执行保护。
5. 完成后执行升级测试。
