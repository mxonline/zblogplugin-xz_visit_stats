# xz_visit_stats v3.0.0 PRD v1.0

状态：**FROZEN（2026-08-25 P0 范围修订）**

> 本次修订依据冻结规则执行：将“可选前端 Beacon、真实用户性能指标 LCP/INP/CLS/TTFB/FCP、屏幕/视口与语言”由 P1 提升为 v3.0.0 P0。版本仍保持 PRD v1.0，不生成常规 v1.1/v1.2。

## 产品定位

**Z-Blog 完整访问统计与分析中心。**

v3.0 的目标不是把插件改造成完整营销平台或安全平台，而是在 v2.0.1 的基础上补齐明显缺失的访问统计能力、恢复已有但未整合的有效功能、完成后台图表化与实时化，并增加一个可选、可关闭、同源的轻量浏览器 Beacon，用于真实用户性能与访客环境增强采集。

## 版本目标

1. 补齐 IP、地域、访客环境、实时、时段、Campaign、AI 来源等基础分析能力。
2. 将当前以表格为主的后台升级为图表 + 明细 + 下钻并存的分析界面。
3. 保留服务器端采集为核心；关闭前端 Beacon 时，PV/UV/IP、来源、蜘蛛、错误等核心访问统计仍完整工作。
4. 可选前端 Beacon 在启用后采集 LCP / INP / CLS / TTFB / FCP、屏幕/视口与浏览器语言，并形成真实用户性能分析。
5. 增加小时级汇总、游标分页、来源维度物化等能力，降低 v2.0 已暴露的大范围查询成本。
6. 保持 v1.3 / v2.x 历史日志兼容，不破坏现有原始事实表和统计口径。

## 后台信息架构

### 总览
- 真人 PV / UV / 独立 IP / 蜘蛛 / 4xx / 5xx / 服务端处理耗时。
- PV / UV / IP 趋势图。
- 真人 / 蜘蛛趋势图。
- 24 小时时段访问分布。
- 来源类型分布。
- 浏览器、操作系统、设备类型分布。
- Beacon 开启且存在数据时，展示真实用户性能摘要：LCP / INP / CLS 及 TTFB / FCP。
- 热门页面、热门 IP、搜索引擎、AI 来源、蜘蛛排行、错误摘要。
- 支持今天、昨天、7 天、30 天、自定义范围及同比/环比。
- 图表与排行榜必须可下钻到对应分析或访问记录。

### 实时分析
- 当前活跃访客（基于可配置短时间窗口，不宣称真实并发在线连接）。
- 最近 5 分钟 / 30 分钟 PV、UV。
- 实时访问流：时间、IP/地域、页面、来源、设备、状态、蜘蛛。
- 当前热门页面、实时来源、实时地域、实时设备、实时蜘蛛、实时错误。
- 使用轻量轮询即可，不要求 WebSocket。

### 访问记录
- 保留 v2.x 组合筛选、分钟快捷筛选、分页与详情。
- 增强单条详情：来源域名、来源类型、Campaign、地域、浏览器、系统、设备、页面标题/文章关联。
- Beacon 数据与单条访问能够可靠关联时可展示性能摘要；不能可靠关联时仅做页面/维度聚合，不伪造一一对应关系。
- 支持 CSV 导出当前筛选结果。
- 支持保存常用筛选条件。
- 大数据量深分页改为游标/Keyset 分页优先，避免无限 OFFSET。

### 页面分析
- 规范化 Path、页面标题、Z-Blog Post ID / Article 关联（可解析时）。
- 真人 PV / UV / IP、蜘蛛、4xx / 5xx、服务端处理耗时。
- 页面趋势、24 小时分布、来源分布、地域分布、设备分布。
- Beacon 开启时增加页面真实用户性能：LCP、INP、CLS、TTFB、FCP，并支持按浏览器/系统/设备/语言/屏幕维度查看。
- 入口页面分析。
- 页面最近访问与下钻。
- 页面标题历史不可准确回填时，必须标记为“升级后可用”或“当前解析值”，不得伪造历史标题。

### 来源分析
- 来源分类固定支持：直接访问、搜索引擎、AI 助手、社交媒体、外部网站、站内来源、广告/活动、其他。
- 来源域名、完整 Referer 明细、着陆页排行。
- 搜索引擎分布。
- AI 助手来源识别，至少覆盖 ChatGPT、Claude、Gemini、Perplexity、Copilot、Grok、DeepSeek，并保留可扩展映射。
- UTM Campaign：utm_source、utm_medium、utm_campaign、utm_content、utm_term。
- Campaign 汇总、趋势、着陆页及下钻。
- 关键词仍仅展示 Referer 实际可解析内容，不承诺完整搜索关键词。

### IP 分析
- 正式恢复并重构现有 IP 分析能力。
- IP 访问排行、访问次数、页面数、首次/最后访问、平均处理耗时。
- 2xx / 3xx / 4xx / 5xx / 404。
- 单分钟最大访问频率。
- 单 IP 最近访问与页面明细。
- 高频访问、404 扫描、扫描工具 UA 等异常提示仅作为分析提示，不自动封禁。
- IP 归属地至少支持国家/地区；城市/ASN/ISP 可按数据源能力降级。
- `ip_mode=masked` 时不得伪造精确地域或原始 IP。

### 访客环境
- 浏览器排行与趋势。
- 操作系统排行与趋势。
- 设备类型：桌面、手机、平板、其他。
- UA 类型与明细下钻。
- Beacon 开启时增加浏览器语言、屏幕分辨率与视口尺寸分析。
- 屏幕、视口和语言只能用于聚合分析，不得与其他字段组合生成新的浏览器指纹或持久身份。

### 蜘蛛分析
- 保留并增强现有蜘蛛排行、趋势、抓取页面、状态码、错误和耗时。
- AI 爬虫单独分类并与普通搜索引擎蜘蛛区分。
- 至少识别主流搜索蜘蛛与主流 AI crawler/agent 的可扩展列表。
- 蜘蛛真实性 DNS / 官方 IP 段验证为 P1，不作为 P0 阻断。

### 错误分析
- 404 / 4xx / 5xx 趋势、状态码分布、高频错误 Path、来源与最近记录。
- 404 来源页面 / Referer 关联。
- 404 被搜索蜘蛛或 AI 爬虫抓取情况。
- 疑似死链提示必须明确为“疑似”，不等同全站爬虫死链扫描。
- 可从错误直接下钻到访问记录、来源或页面分析。

### 性能分析
- 服务端性能：继续使用 `DurationMs`，展示服务端处理耗时趋势、慢页面、慢请求。
- 真实用户性能（Beacon 开启时）：LCP、INP、CLS、TTFB、FCP。
- LCP / INP / TTFB / FCP 以毫秒展示；CLS 使用无量纲数值。
- LCP / INP / CLS 至少提供 P75 聚合；TTFB / FCP 至少提供 P50/P75 或等价稳定分位数分析。
- 指标不可用或浏览器不支持时必须允许 NULL/缺失，不得补零伪造。
- 前端真实用户性能与 `DurationMs` 必须使用不同字段、不同名称、不同图表或明确分区展示，禁止混淆“服务器处理耗时”和“浏览器体验性能”。
- 支持按页面、浏览器、操作系统、设备、语言、屏幕/视口维度下钻。

### 设置与维护
- 采集启停、Referer、UA、蜘蛛、IP 完整/脱敏、保留期、自动清理。
- 可信代理/CDN真实 IP：REMOTE_ADDR 为基础；仅在请求来自可信代理时才接受 CF-Connecting-IP、X-Forwarded-For、X-Real-IP 或自定义 Header。
- 支持可信代理 IP/CIDR 配置，禁止无条件信任转发头。
- 小时/日汇总状态、重建、迁移、PathKey 回填、数据健康状态。
- 导出限制、实时窗口、保存筛选。
- 前端 Beacon 独立开关；关闭后不得加载 Beacon 脚本、不得发送前端性能请求。
- Beacon 采集项可显示当前状态；至少覆盖真实用户性能、屏幕/视口、语言。

## 采集架构原则

### 服务器端核心采集
服务器端继续负责访问、IP、Referer、UA、蜘蛛、状态码、服务端处理耗时、Path 等事实数据。即使 Beacon 关闭，核心访问统计仍必须完整可用。

### P0 可选前端 Beacon
- Beacon 是 v3.0.0 P0 功能，但对站点管理员而言必须是可选开关。
- 默认以“关闭”为安全兼容基线；管理员主动开启后才向前台输出轻量脚本。
- 优先使用浏览器原生 Performance API / PerformanceObserver 获取指标，不依赖外部统计服务。
- 上报优先使用同源 `navigator.sendBeacon()`；不可用时可使用同源 `fetch(..., {keepalive:true})` 等非阻塞降级。
- Beacon 请求不得阻塞首屏渲染，不得因统计失败影响页面业务逻辑。
- 只采集 PRD 明确允许的性能/环境字段，不采集 DOM 文本、输入框内容、表单值、Cookie 内容、LocalStorage 内容、键盘输入或其他页面正文数据。
- 屏幕/视口/语言不得用于构造新的持久浏览器指纹。
- Beacon 接口必须限流、校验字段类型/长度、拒绝超大 payload，并防止跨站滥用；优先同源接收。
- Beacon 数据应有独立的数据职责边界，可按实现需要采用独立表或明确的性能事实结构；不得污染服务器访问事实字段语义。

## 数据与兼容约束

- 继续保留 v2.x 原始访问事实表作为核心历史来源，除非 Codex 在真实代码审查后证明需要迁移；不得为了 3.0 清空历史日志。
- VisitorHash 仍是匿名统计标识，不得描述为登录用户身份。
- 脱敏 IP 历史数据无法还原。
- Referer、UA 关闭期间的历史缺口不可回填。
- 新增 UTM、地域、页面标题、AI 来源等维度，能从历史 Url/Referer/IP/UA 可靠推导的可回填；不能可靠推导的必须明确“升级后统计”。
- Beacon、LCP/INP/CLS/TTFB/FCP、屏幕/视口与语言不存在于 v2.x 历史日志中，必须明确为“升级到 v3.0 且开启 Beacon 后统计”，禁止伪造历史数据。
- 精确跨日 UV/IP 仍不得简单相加每日/小时 UV/IP。
- 所有汇总和回填任务必须幂等、可分批、可恢复、可安全重建。

## 性能与安全要求

- 3.0 必须针对 v2.0 已知的宽范围 DISTINCT、来源解析、页面聚合、深 OFFSET 分页风险做结构性优化。
- 高频来源、Campaign、环境、小时维度优先使用物化维度和汇总，避免每次扫描完整原始日志。
- 所有后台输出做 HTML 转义；所有写操作使用 CSRF 防护。
- 可信代理配置不得造成客户端伪造 IP。
- CSV 导出必须受权限、时间范围和最大行数限制。
- Beacon endpoint 必须验证来源/请求方式、限制 payload、限制频率并安全处理所有输入；不得成为公开任意写入或放大攻击入口。
- Beacon 脚本应尽量小且异步/延迟执行；关闭时前台额外开销应为 0。
- 插件任何服务端或 Beacon 异常不得影响前台页面正常响应。

## P0 验收标准

- v2.0.1 可原地升级至 v3.0，历史日志与现有统计不丢失。
- 新安装与 v2.0.1 升级后的最终 schema / 配置一致。
- 所有 P0 模块可在真实 Z-Blog 后台打开并正确显示空数据/有数据状态。
- Dashboard 图表、实时、IP、环境、来源、Campaign、AI 来源、蜘蛛、错误、性能均能下钻到对应明细。
- 可信代理开启/关闭、可信/不可信来源头均有真实测试。
- CSV 导出与保存筛选可用且权限正确。
- Beacon 关闭时：页面不加载 Beacon、不产生 Beacon 网络请求，服务器端统计正常。
- Beacon 开启时：至少在支持的现代浏览器采集并落库 LCP / INP / CLS / TTFB / FCP、屏幕/视口、语言；不支持的指标以缺失处理。
- Beacon 输入校验、同源/滥用防护、限流和异常隔离通过测试。
- 性能分析中 `DurationMs` 与真实用户指标完全分离；LCP/INP/CLS 至少能显示 P75 聚合。
- 10 万与 100 万级数据重新验证关键查询；1000 万如未实测必须继续明确标记为估算，不得虚假承诺。
- PHP syntax、自动测试、本机 Z-Blog、真实数据库升级、GitHub CI 全部通过。

## 最终冻结规则

本 PRD 为 **v3.0.0 唯一冻结需求基线**。除非出现以下情况，否则不再生成 v1.1/v1.2：

- P0 功能新增或删除；
- 统计语义改变；
- 用户可见数据口径改变；
- 发现无法安全实现的重大兼容问题。

普通实现细节、表字段、类/函数命名、索引组合由 Codex 在读取真实代码和数据库后决定，不再由需求阶段反复设计。
